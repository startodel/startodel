# Design and verify a Track

Start with `get_profile` and `list_topics` to personalize the plan and find reusable Topics. After research and agreement on the outline, use `create_track`, `upsert_topics`, `add_edges` and `attach_topics_to_track`.

1. **Personalize the outcome.** Combine the Onboarding Questionnaire with what you already know to choose the starting Topic, depth, pace, prerequisites and language. Use examples from the learner’s current project or domain. If they ask to learn from scratch, teach the requested foundations in that technology. Leave out another framework’s code, terminology and side-by-side comparisons unless the learner explicitly asks to compare technologies in this conversation. Confirm the choice if their background or goal is uncertain.
2. **Verify the sources.** Before designing the Track, use your own web and repository tools to verify the current release and read a primary source for each technology. Check official documentation against recent release notes, a maintainer article or the primary repository. Proceed only when each design decision has a supporting source URL and its version or date.
3. **Choose a mode from the goal.** Agree on an outline that ends in an observable decision or working result.
   - **Comparison mode** only when the learner explicitly asks, for example “How do X and Y differ?” Build a mental model of each, including its core problem and architecture. Apply both to the same case. Derive tradeoffs and decision criteria, then vary a constraint. End with a scenario-based Quiz asking which fits the new case, followed by “Why?” in chat.
   - **Deep-dive mode** for “Teach me X.” Connect a mental model to the learner’s concrete goal. Start with a working setup or configuration, trace the internals that explain its behavior, then diagnose a production failure. End with an Exercise where the learner changes the setup and verifies the result independently.
4. **Phase 1 — save the full roadmap before drafting Lessons.** Create the private Track with a one- or two-sentence description of the learning outcome and scope. Mention a major version if it defines the scope. Set `language` explicitly when known, using a lowercase tag such as `en`, `ru` or `pt-br`. Put versioned documentation and dated release notes in Track Sources. Reuse matching Topic Slugs, create every missing Topic, add the prerequisite-to-dependent edges as a directed acyclic graph, and attach all Topics in teaching order. Read back the sources with `get_track` and the complete roadmap with `get_track_graph`. Share the Track URL so the learner can review the sequence before you write prose.
5. **Phase 2 — write Lessons for one or two Topics per pass.** Call `get_guide` with `track` set to this Track’s UUID or slug. Take the next batch from `authoring.nextTopics`, which lists planned Topics with zero Lessons in Track order. Inspect existing Lessons on reused Topics. Follow [Write a Lesson with Blocks](07-lessons-and-blocks.md) for each Topic in the batch. Read the saved Lessons back, then call `get_guide` with the same Track to resume. Once every planned Topic has a Lesson the list is empty. Use `nextSteps` when the learner wants to study, review or continue a GrillSession.
6. **Revise the roadmap.** Use `update_track` for a changed goal, language or sources. Identify it by `id` or `slug`. To change its slug, pass its current `id` and the new `slug`. Use `update_topic` to revise a Topic’s title or summary across its Tracks. Use `remove_edge` for an incorrect prerequisite and `detach_topic_from_track` to remove one membership while keeping its Lessons.
7. **Delete at the requested scope.** Use `delete_track` with its `id` or `slug` to remove the Track and its memberships. Its GrillSessions become unscoped. Every Topic stays in the Topic Catalog, even after its last membership is removed, together with its Lessons, progress and prerequisite edges. Use `delete_topic` with its `id` or `slug` only when the learner wants to erase the Topic across every Track. This also deletes its edges, Lessons, Lesson Progress, Quiz Attempts, Mastery, ReviewItem and linked Grill Questions.
