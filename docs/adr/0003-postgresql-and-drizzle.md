# 3. PostgreSQL and Drizzle

## Status

Accepted

## Context

The learning model has relationships that must survive concurrent writes. For example, a Profile belongs to one user and a TopicEdge connects two Topics in a particular direction. Self-hosted installations need a reproducible way to create and upgrade these tables.

## Decision

Use PostgreSQL for transactions, foreign keys, and uniqueness constraints. Define tables in TypeScript with Drizzle ORM and commit the SQL migrations generated by Drizzle Kit. Use node-postgres (`pg`) through Drizzle's native adapter. Its pool opens connections on demand, supports a bounded connection wait, and can be closed explicitly after a health check. Its TypeScript package supplies the Node runtime declarations used by the server and database tooling.

## Consequences

Running migrations requires PostgreSQL and a connection URL. Contributors can inspect the SQL before applying it. A Progress row records one completed Lesson for a user and identifies the Track through that Lesson. The client factory takes a URL and leaves connection cleanup to the caller.

See [Drizzle's PostgreSQL drivers](https://orm.drizzle.team/docs/get-started-postgresql) and the [node-postgres pool documentation](https://node-postgres.com/apis/pool).
